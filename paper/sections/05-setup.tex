\section{Setup}
\label{sec:setup}

\paragraph{Platforms.} One node of 8 A100-SXM4-80GB GPUs connected by NVLink, and one TPU
v5e-8 host (8 chips of 16\,GB, connected by the chips' own interconnect)
\citep{nvidiaA100,tpuv5e}. The A100 has 5$\times$ the memory per device; the v5e's matrix
unit multiplies in bfloat16 by default. For the host boundary, two of the A100 nodes.

\paragraph{The block benchmark.} Most systems measurements use one simplified
transformer block: six square $d\times d$ matrices (attention q, k, v, o and a two-layer
MLP of width $d$), one head, no normalization parameters, synthetic inputs, squared
error. So $P = 6d^2$: at $d{=}2048$ that is 25.2M parameters and a 96\,MiB float32
update. Each generation evaluates the whole population on one batch of 8 sequences of
length 32. The placement grid is $d\in\{512,2048\}$, two populations per width (256 and
1024 at $d{=}512$, 128 and 256 at $d{=}2048$), and $D\in\{1,2,4,8\}$; the cost grid of
Appendix~\ref{sec:systems-ablations} is wider. The simplifications change arithmetic intensity and
memory, so absolute ratios belong to this workload, and we test whether the placement
preference carries over to a real model.

\paragraph{The real model.} Qwen2.5-0.5B \citep{qwen25}, for three things: timing one
full update under both placements on the v5e (Figure~\ref{fig:f9}); the alignment of
that update with the gradient-descent direction, also at 1.5B (Section~\ref{sec:quality}); and
training on Countdown on one A100. The timing comparison evaluates candidates in a single batch for low-rank
noise and one at a time for regenerated full-rank noise. This changes activation memory
and throughput across perturbation types; each placement comparison keeps the evaluation
procedure fixed. For the timing and alignment experiments the fitness is the model's
next-token loss on a fixed batch of eight Countdown prompts (the mean negative
log-likelihood of each token given the ones before it), which is differentiable, so its
gradient can be computed exactly for reference.

\paragraph{Protocol.} Per configuration, 3 warm-up generations (the first compiles), then 5 timed
repeats (7 for the host boundary and the ranking step); we report the median, and every timed call waits for
the device to finish. Matmul precision is fixed per experiment and recorded: the scaling
and placement sweeps use full precision so that it is the same at every device count;
the cost grid uses the default setting
(Appendix~\ref{sec:systems-ablations} reports the timing comparison). Both platforms run the
same (model size, population, perturbation type, datatype) configurations. We record configurations that do not fit as out of memory (OOM), keeping the
model and population fixed so memory limits remain part of the comparison.

\paragraph{Scope.} One host per platform, where an all-reduce is cheapest, plus one
TCP-connected pair of hosts; a simplified block and one real model family; one task
at one model size with three seeds. Results are stated within those limits.

\paragraph{Provenance.} Configurations and result records include their code versions and environments.
Every figure and table is generated from those records (Appendix~\ref{sec:repro}).
